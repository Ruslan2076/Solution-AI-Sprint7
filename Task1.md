## Паспорт ИН-01. Приоритизация разбора подозрительных операций

### 0. Канвас оценки инициативы

| Вопрос | Что фиксируем |
|---|---|
| Ценность | Правила помечают ~35 тыс. операций в месяц, разбирается ~10 тыс., порядок разбора задаёт сумма; ~25 тыс. (≈71%) не разбираются вовсе. Разбор стоит ≈375 ₽ (45 млн ₽ ФОТ / 120 тыс. разборов в год), одна эскалация ≈9,4 тыс. ₽ (3,75 млн ₽ в месяц / 400). Каждый процентный пункт доли эскалаций среди 10 тыс. разборов даёт +100 случаев на расследование в месяц без найма; при нынешних 4% тем же 100 случаям соответствуют 2 500 дополнительных разборов, 500 часов и ≈0,94 млн ₽ в месяц. Снимаемый риск — пропуск схем, за который банк за год получил два предписания. Эскалация не равна подтверждённой схеме, поэтому эффект в эскалациях — промежуточный показатель. |
| Выполнимость | Тип задачи понятен: порядок по оценке операции на таблице, истории операций и тексте назначения платежа. Данные внутри банка. Сложные части: агрегаты по клиенту и контрагенту за окна, свободный текст назначения, встраивание оценки в рабочее место финмониторинга без изменения процедуры ПВК. |
| Данные | Разрыв с планом закрытия. Метки «схема / не схема» нет; обучаемся на отметке «эскалировано» по разобранным операциям. Разобранные отобраны правилами и с приоритетом крупных сумм, поэтому выборка смещена, а непроверенная операция не равна чистой. Нужна контрольная случайная выборка из неразобранных помеченных операций, разобранная финмониторингом, чтобы честно измерить качество. Подтверждённые случаи (единицы, через месяцы) используются только для проверки, что они попадают в верх очереди. Право использовать историю операций для обучения — ВЮ-07. |
| Риск | Пропуск: схема осталась в неразобранной части очереди, риск претензий надзора. Ложное срабатывание: лишний разбор за ≈375 ₽; клиента модель не блокирует, поэтому число приостановок от неё напрямую не растёт. Модель учится на прошлых решениях правил и аналитиков и не гарантирует обнаружения новых схем. Регуляторно решение встраивается в ПВК и не отменяет установленной процедуры выявления и фиксирования; уровень риска клиента от внешней платформы «Знай своего клиента» — один из входов, окончательная оценка за банком. |
| Вывод | Берём с условием: модель только упорядочивает очередь помеченных операций; операции, обязательные к разбору по ПВК, идут вне ранжирования; комплаенс подтверждает допустимость нового порядка разбора (ВЮ-06); финмониторинг разбирает контрольную случайную выборку. |

### 1. Карточка триажа

| Поле | Значение |
|---|---|
| Инициатива без слова «AI» | Операции, помеченные правилами и внешними сигналами → очередь финмониторинга, упорядоченная по вероятности того, что разбор закончится эскалацией на расследование. |
| Какое действие изменится | Порядок разбора: вместо «крупные суммы первыми» аналитик берёт операции с наибольшей оценкой. Состав очереди и сама процедура разбора не меняются. |
| Где нужна обучаемая закономерность | Оценка операции. Остальное детерминировано: пороговые правила и внешние сигналы ставят операцию в очередь; накопительные проверки на дробление (число и сумма платежей клиента и пары «клиент — контрагент» за период) работают как правила и как признаки; операции, обязательные к разбору по ПВК, идут вне ранжирования; решение об эскалации, приостановке и фиксации принимает сотрудник. |
| Чего не хватает, допущения | Метки «схема» нет, есть три разных следа, которые нельзя смешивать. Неизвестно, закреплён ли приоритет крупных сумм в ПВК или это сложившаяся практика (ВЮ-06). Допущение: история разборов хранится с отметкой исхода по каждой операции. |

### 2. Постановка

| Поле | Значение |
|---|---|
| Бизнес-действие | Порядок разбора очереди финмониторинга. |
| Объект и единица решения | Операция, помеченная правилами или внешним сигналом. Признаки считаются по операции, клиенту и контрагенту за скользящие окна. |
| Момент | При постановке операции в очередь, в течение минут; оценка асинхронна к проведению платежа и в синхронный путь проведения не встраивается. |
| Операция | Порядок (ранжирование) по оценке классификатора «уйдёт на эскалацию / нет». |
| Модальность | Таблица (сумма, канал, ОКВЭД, тариф и лимиты, уровень риска клиента от внешней платформы), время (история операций клиента и контрагента), текст (назначение платежа в свободной форме). |
| Выход модели | Оценка на операцию и основные признаки, которые на неё повлияли. |
| Бизнес-выход | Очередь в рабочем месте финмониторинга: сверху операции, обязательные к разбору по ПВК, ниже остальные по убыванию оценки, у каждой причины. Рабочая точка — верхние ~10 тыс. в месяц, по пропускной способности службы. |
| Источник правильного ответа | Обучение: отметка «эскалировано на расследование» по разобранным операциям, известна в момент разбора. Дополнительная проверка: исход расследования (ничем / отказ в проведении), известен через недели. Контроль: формально подтверждённые случаи, единицы, известны через месяцы; в обучение не идут. Неразобранные операции меток не получают. |
| Конвейер | Правила и внешние сигналы ставят в очередь (детерминированно) → расчёт агрегатов и накопительных проверок (детерминированно) → признаки из назначения платежа (обучаемое звено или словарь, решается в задании по модели) → оценка операции (обучаемое) → сортировка с обязательными позициями (детерминированно) → решение сотрудника → его отметка возвращается как новая метка. |
| Альтернативные постановки | 1) Поиск схем среди непомеченных операций (20–25 млн в месяц): поиск аномалий без меток, необычное не равно подозрительному; различает ВБ-01. 2) Единица решения — клиент за период, потому что транзит и дробление видны в поведении, а не в одной операции; различает ВБ-02. 3) Классификация по подтверждённой схеме — отклонена: метки единичны и запаздывают на месяцы. |

### 0. Канвас оценки инициативы

| Вопрос | Что фиксируем |
|---|---|
| Ценность | Андеррайтинг разбирает пакет документов в среднем 1,5 часа. Эффект в часах равен сэкономленному времени на заявку, умноженному на число заявок в месяц; число заявок в материалах не дано (ВБ-16), поэтому в деньгах эффект пока не считается. Дополнительно: извлечённые показатели нужны как вход для ИН-10 и сокращают срок решения по заявке. |
| Выполнимость | Извлечение структуры из документов — операция, для которой есть готовые модели, обучать с нуля не требуется. Сложности: разнородные форматы (Excel, выгрузки разных бухгалтерских систем, сканы, фото с телефона), таблицы в отчётности, встраивание в кредитный процесс. |
| Данные | Можно начинать пилот при условии, что прошлые значения показателей хранятся вместе с исходными документами; иначе разрыв с планом: андеррайтеры размечают выборку пакетов по гайдлайну, это их текущая работа. Право обработки документов поручителей-физлиц и выписок из других банков — ВЮ-08. |
| Риск | Неверно извлечённое значение может исказить кредитное решение. Защита: арифметический контроль, ссылка на место в документе у каждого показателя, подтверждение андеррайтером. Риск склонности соглашаться с предзаполненным значением, нужен выборочный аудит. Автоматизированного решения о кредите нет, барьер ИН-12 сюда не переносится. Если модель внешняя, вопрос передачи ПДн и сведений банковской тайны за контур решается в задании по размещению. |
| Вывод | Берём. Масштаб эффекта уточняется ответом на ВБ-16. |

### 1. Карточка триажа

| Поле | Значение |
|---|---|
| Инициатива без слова «AI» | Пакет документов кредитной заявки → предзаполненная карточка финансовых показателей заёмщика со ссылкой на источник каждого значения. |
| Какое действие изменится | Андеррайтер проверяет и подтверждает предзаполненные показатели вместо ручного переноса из документов. |
| Где нужна обучаемая закономерность | Распознавание текста и таблиц на сканах и фото; определение типа документа; извлечение показателей из документов нефиксированной формы. Детерминированно: разбор Excel и выгрузок известных бухгалтерских систем; контрольные соотношения отчётности; сверка итогов выписки с суммой её операций; передача полей с низкой уверенностью или не прошедших контроль андеррайтеру. |
| Чего не хватает, допущения | Перечень показателей, число заявок, доля сканов и фото против Excel и выгрузок (ВБ-16). Допущение: перечень показателей утверждает кредитный риск. |
| Вердикт | Гибрид |

| Поле | Значение |

| Бизнес-действие | Подтверждение показателей андеррайтером вместо ручного ввода. |
| Объект и единица решения | Показатель в документе заявки (значение за период); пакет заявки собирается из них. |

## Паспорт ИН-08. Прогноз ухода клиента в другой банк

### 0. Канвас оценки инициативы

| Вопрос | Что фиксируем |
|---|---|
| Ценность | В материалах известно: ~180 тыс. активных клиентов; ~120 жалоб в месяц после приостановок, часть жалующихся уходит. Доля ушедших и доход банка на клиента не даны, поэтому эффект в деньгах не считается до ответа на ВБ-17. Измеряется через сравнение группы контакта с контрольной группой: доля удержанных, сохранённый доход. |
| Выполнимость | Классификация по табличным данным с правильными ответами из истории — самая быстрая и дешёвая для проверки постановка. Сложность не в модели, а в определении ухода и в том, есть ли процесс удержания, куда отдавать список. |
| Данные | Можно начинать пилот после фиксации определения ухода: метка вычисляется из истории операций правилом, ручная разметка не нужна. Новые клиенты без истории — холодный старт, на них прогноз ограничен. После запуска контакты меняют исход, поэтому метки смещаются (петля обратной связи); нужна постоянная контрольная группа без контакта. Право использовать историю операций для цели удержания — ВЮ-09. |
| Риск | Ложное срабатывание: лишний контакт менеджера и раздражение клиента. Пропуск: клиент ушёл без попытки удержания. Регуляторный барьер не виден, решений, затрагивающих права клиента, модель не принимает. |
| Вывод | Берём с условием: бизнес отвечает на ВБ-08 (определение ухода, действие, ёмкость контактов). Если процесса удержания нет, на его место встаёт ИН-15. |

### 1. Карточка триажа

| Поле | Значение |
|---|---|
| Инициатива без слова «AI» | История операций и продуктов клиента → список клиентов с наибольшей вероятностью ухода на горизонте, который задаст бизнес. |
| Какое действие изменится | Менеджер связывается с клиентами из верха списка до их ухода. |
| Где нужна обучаемая закономерность | Оценка вероятности ухода. Детерминированно: вычисление метки ухода по правилу из истории; сортировка; отсечка по числу контактов, которые может сделать удержание; исключение клиентов, с которыми менеджер уже работает. |
| Чего не хватает, допущения | Определение ухода, горизонт, процесс и ёмкость удержания (ВБ-08); доля ушедших и доход на клиента (ВБ-17). Допущение: в банке есть сотрудники, которые ведут клиентов МСБ и могут выполнять контакты. |
| Вердикт | ML-кандидат |

### 2. Постановка

| Поле | Значение |
|---|---|
| Бизнес-действие | Выбор клиентов для контакта по удержанию в периоде. |
| Объект и единица решения | Клиент (юрлицо или ИП). |
| Момент | Пачкой, раз в период удержания (неделя или месяц — по ответу на ВБ-08). |
| Операция | Категория (уйдёт / не уйдёт на горизонте); список получается сортировкой по оценке. |
| Модальность | Таблица (продукты, тариф, ОКВЭД, жалобы и приостановки) и время (динамика оборотов, числа операций, остатков). |
| Выход модели | Оценка вероятности ухода на клиента и основные признаки. |
| Бизнес-выход | Список верхних K клиентов на период с причинами, K равно ёмкости удержания. |
| Источник правильного ответа | Факт ухода по выбранному определению, вычисленный из истории операций; становится известен по истечении горизонта. |
| Конвейер | Расчёт метки по правилу (детерминированно) → признаки по окнам (детерминированно) → оценка (обучаемое) → сортировка, исключения, отсечка по K, выделение контрольной группы (детерминированно) → контакт менеджера → исход контакта фиксируется. |
| Альтернативные постановки | 1) Уход = закрытие счёта: метка надёжная, но поздняя. 2) Уход = падение оборотов ниже порога при открытом счёте: ловит частичный уход, порог задаёт бизнес. 3) Порядок по ожидаемой потере дохода (вероятность × доход клиента), если бюджет удержания ограничен: модель та же, меняется сортировка. Различают ВБ-08 и ВБ-17. |
